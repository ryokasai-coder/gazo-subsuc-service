## 1. プロジェクト概要

- **DESIGN BOX** ＝ 画像制作サブスクサービス（月額5,000円・月10回）。テンプレ選択 → AI生成 → Google Drive納品。
- 申込〜制作管理〜納品〜請求〜解約までを一元管理。
- **本番:** https://gazo-subsuc-service.vercel.app
- **GitHub:** https://github.com/ryokasai-coder/gazo-subsuc-service

## 2. 技術スタック

- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- Supabase（DB + Auth + RLS）
- Gemini 画像生成（`gemini-3.1-flash-image` / Nano Banana 2）
- Resend（メール）／ Vercel Cron（毎朝9時リマインダー等）
- `npm run dev` は **port 3001**

> ⚠️ `AGENTS.md` にある通り、このリポジトリの Next.js は破壊的変更を含む版です。コードを書く前に `node_modules/next/dist/docs/` の該当ガイドを確認してください。

## 3. セットアップ

```bash
git clone https://github.com/ryokasai-coder/gazo-subsuc-service.git
cd gazo-subsuc-service
npm install
# .env.local を用意（値はプロジェクト管理者から受け取る。リポジトリには絶対にコミットしない）
npm run dev   # http://localhost:3001
```

### 環境変数（`.env.local` / Vercel に定義。**値はチャットやコミットに出さない**）
- `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `RESEND_API_KEY`
- `ADMIN_EMAIL`
- `CRON_SECRET`
- （画像生成用）Gemini APIキー

`.env.local` は `.gitignore` 済み。秘密情報が漏れたら**必ず失効（revoke）**してから再発行すること。

## 4. アーキテクチャ地図（画像生成まわり）

| ファイル | 役割 |
|---|---|
| `lib/design-prompts.ts` | テンプレの**入力欄定義**（`TEMPLATE_FIELDS`）と**AIプロンプト組立**（`buildPrompt`）。パンフレットは `buildBrochurePrompt`、飲食11種は `buildFoodPrompt`＋`FOOD_TEMPLATE_SPECS`、参考画像方式は `buildReferencePrompt`＋`REFERENCE_TEMPLATE_IDS`。 |
| `lib/reference-images.ts` | 参考画像方式の**固定参考画像(Image 1)をbase64同梱**＋共通システム指示（`SYSTEM_INSTRUCTION`）。**server専用**（生成APIのみimport）。 |
| `components/forms/ImageRequestForm.tsx` | 依頼フォーム。**選択カード配列 `TEMPLATES`** ＋ 素材アップ欄 `MATERIAL_UPLOAD`。パンフレット一括は `BrochureBuilder`。 |
| `app/api/design/generate/route.ts` | 生成API（stateless）。参考画像ありは parts=[参考画像, 顧客画像, prompt]＋systemInstruction、なしは [prompt, photo]。 |
| `app/api/design/deliver/route.ts` | 納品（Drive保存＋使用回数消費）。 |

## 5. ★テンプレ追加の鉄則（最頻出のハマりどころ）

新テンプレは**関連ファイル全部**に入れないと選択画面に出ない／動かない。

1. `lib/design-prompts.ts` … `TEMPLATE_FIELDS`（入力欄）＋ `buildPrompt`（プロンプト）
2. `components/forms/ImageRequestForm.tsx` … `TEMPLATES`（選択カード）＋ `MATERIAL_UPLOAD`（素材アップ欄）
3. **参考画像方式の場合はさらに** `lib/reference-images.ts` の `REFERENCE_IMAGES`（参考画像バイト）＋ `design-prompts.ts` の `REFERENCE_TEMPLATE_IDS` に登録

> `shop-interior`/`access-info` はパンフレット専用（`BROCHURE_PAGES`）なので `TEMPLATES` には意図的に非登録。

## 6. ブランチ / PR 運用（推奨・チーム化にあたり移行）

これまでは `main` 直push運用でしたが、複数人で触るため**フィーチャーブランチ＋PR**へ移行を推奨します。

```
main（保護・自動デプロイ）
 └ feat/xxx  … 作業ブランチ → PR → Vercelプレビューで確認 → レビュー → main へマージ
```

- `main` への直pushは避け、PR経由に。PR単位で Vercel のプレビューURLが出るので、そこで目視レビュー。
- コミットメッセージは日本語でOK（既存の流儀に合わせる）。
- **本番反映（mainマージ／デプロイ）は承認を得てから。** 外部送信・課金・削除・公開は勝手に実行しない。

## 7. 検証ゲート（マージ前に必ず通す）

- `npx tsc --noEmit` … 型エラー0
- `npm run build` … ビルド成功（全ページ）
- 参考画像方式のプロンプトは `node --experimental-strip-types` で出力を目視（`buildPrompt` の差し替え文を確認）
- **DBスキーマを変えたら本番マイグレーション必須**（Vercel/Supabaseは自動適用しない。列追加のまま未migrateだと `column does not exist` で機能全体が壊れる）
- デプロイ後は **Vercelダッシュボードで成功を必ず目視**（サイレント失敗対策）
